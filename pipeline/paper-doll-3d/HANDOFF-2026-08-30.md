## 1. What this lane is

We own a straight-on photo of nearly every bottle we sell. Its OUTLINE is the
true profile. Combined with real millimetres, that is enough to rebuild the
bottle in 3D automatically — no sculpting.

| shape | operation | second axis from |
|---|---|---|
| **round** (cylinder, flask, sphere) | **lathe** — revolve the outline 360° | diameter |
| **boxy** (square, rectangular, disc flask) | **extrude** — sweep the footprint upward | width **and** depth |
| **sculpted** (Diva, Diamond) | **neither — deferred** | a silhouette shows the front only |

Blender is the geometry engine **only**, headless. No materials, no lighting,
no rendering. The browser draws glass/frost/metal, assigned by mesh name. That
is precisely why this lane does not hit the wall that stopped the manual
Blender effort (glass materials, lighting, render setup).

## 3. The GLB contract

Every file contains **one mesh + two empties, and no materials**:

```
BB_BTL_<body_id>     the glass. Closed solid. POSITION + NORMAL only.
                     NO material, NO texture, NO UVs.
BB_ATTACH_NECK       empty at the RIM (y = bare height). Closures
                     parent-and-zero here.
BB_REF_SHOULDER      empty at the neck base. Drives the boxy round-neck
                     blend. NOT an attach point.
```

Y-up, **metres**, ~13,442 verts, ~474 KB each.

**The rim datum is not a preference — it is the existing house contract.**
`scripts/paper-doll-3d/components_17415.py` parents every closure to the neck
datum at `location (0,0,0)` — *"origin IS the rim datum"* — and
`build-master-scene.py` places `BB_ATTACH_NECK` at `(0, 0, s["height"])`,
commented *"closure seating plane"*. Move it and every cap in the configurator
sits wrong.

## 4. Pipeline

```bash
cd pipeline/paper-doll-3d

# 1. dimensions — from the live catalogue, never from pixels
python3 scripts/harvest_live_dims.py --all --out bodies-3d-dims.csv

# 2. silhouettes — PSD body layer (system Python; Blender has no psd_tools)
python3 scripts/extract_psd_silhouette.py --from-csv bodies-3d-dims.csv

# 3. QA the silhouettes against catalogue proportions
python3 scripts/qa_silhouette_aspect.py

# 4. collapse SKUs -> distinct bodies (writes bodies.csv + sku-to-body.csv)
python3 scripts/group_bodies.py

# 5. build
blender --background --python scripts/bottle_bodies.py -- \
    --ledger bodies.csv --cutouts silhouettes --out glb

# 6. verify — mesh integrity + renders
blender --background --python scripts/verify_glb.py -- \
    --glb glb/*.glb --out renders/verify

# 7. LOOK AT IT — the numeric gates cannot catch a visibly wrong body
python3 scripts/contact_sheet.py && open renders/all-bodies.png
```

Add `--sku X` to any step for one body. Blender is `/opt/homebrew/bin/blender`
(5.2.0 LTS). Step 2 takes ~19 min for the full catalogue; the rest are seconds
to a few minutes.

| script | does |
|---|---|
| `harvest_live_dims.py` | parses cached PDPs for Height/Width/Depth/Diameter/neck |
| `extract_psd_silhouette.py` | PSD body layer → cached transparent PNG |
| `qa_silhouette_aspect.py` | traced aspect vs catalogue aspect; flags fused closures |
| `group_bodies.py` | 1,345 SKUs → 56 bodies + `sku-to-body.csv` |
| `bottle_bodies.py` | the lathe/extrude builder + dimension gate |
| `verify_glb.py` | manifold check, datum check, Workbench render |
| `contact_sheet.py` | assembles `renders/all-bodies.png` — the visual gate |

## 5. Rules that cost real time to find — Blender side

**`screw.merge_threshold` defaults to 0.01 m = 10 mm in Blender 5.2.** A 9 ml
bottle has a ~10 mm *radius*, so `use_merge_vertices = True` without setting the
threshold welds the whole body into its own axis. Set 1e-6.

**Dimensions come from the live site, not the silhouette.** PDPs publish *Item
Height without Cap / Item Width / Item Depth / Item Diameter* and the neck
thread. A photo cannot reveal depth — the live site can.

**The live site also states the SHAPE.** A PDP printing a Diameter is round; one
printing Width **and** Depth is boxy. No hand-filled column.

**Never read a published `Item Width` as a diameter.** Empire 50/100 and Sleek
30/100 publish width only and are visibly rectangular. Coercing builds
cylinders. Those bodies are marked `shape_class = unknown` and skipped — and
both coercion paths (grouper and builder) are explicitly closed.

**A boxy neck is a FULL-DIAMETER circle, and the depth ratio must not carry into
it — but clamp the converged depth to the catalogue depth.** Holding the ratio
at the neck turned flat disc flasks (Crcl 105×89×29) into mushrooms on a stalk;
converging unclamped then doubled the body to 63.7 mm deep.

**The seat is not the mouth.** Derive the shoulder — widest point, walk up,
first height below ~72% of max half-width. But the shoulder is a *reference*
datum; the **attach** datum is the rim (§3).

**`np.convolve(mode="same")` zero-pads** and shrinks foot and mouth radii — the
two places the outline must stay honest. Pad with the edge value.

**Free the mesh datablock, not just the object**, or a batch leaks unboundedly.

**Representative silhouettes: consensus (median profile) across the body group.**
Every size rule failed in one direction or the other:
- *tallest* → sprayer dip tubes out-height squat bodies (`GBRnd128Spry*`, traced 10.15:1 against a catalogue 1.20:1)
- *largest* → bulb sprayers out-area slim bodies (`GBSlm50AnSpTsl*`, 1.01:1 against 3.90:1)
- *smallest* → closure crops (`GBRnd78RdcrShnBlkTall`, a black cap)

and **both extremes can match the expected aspect by coincidence**, so no
numeric gate sees them.

> **The contact sheet is the gate, not a number.** Always look at
> `renders/all-bodies.png` before shipping a batch. It caught two 84/74-SKU
> bodies rendering as mushrooms that every numeric check passed.

## 6. Rules that cost real time to find — React / r3f side

**Never use drei `<AccumulativeShadows>` with transmissive glass.** It re-renders
the scene into an offscreen buffer and that pass draws the body **opaque
white**. The material stays correct (`transmission: 1`), so it reads as a
material bug and is not one. This one cost the most time.

**`thickness` and `attenuationDistance` are WORLD UNITS — metres here.**
`thickness: 1.6` is 1.6 *metres* of glass across a 70 mm bottle; it absorbs
everything and renders solid. Real container glass ≈ `0.0025`.

**Y-up.** `export_yup` rotates Blender's Z-up, so a datum's height is
`.position.y`. Reading `.z` reports `0.00 mm` for every body and makes a correct
attach point look broken.

**three.js assigns a DEFAULT material to any primitive that has none**, so
counting materials on the loaded mesh always returns ≥ 1. For what the FILE
declares, read `gltf.parser.json.materials?.length ?? 0`.

**`Box3.setFromObject` walks children.** Anything parented to a datum — the
marker ring today, a closure tomorrow — is measured as part of the bottle. It
reported 0.61 mm of drift that does not exist. Measure
`mesh.geometry.boundingBox`.

Colour comes from `attenuationDistance` + `attenuationColor`, not `color` —
which is how real amber and cobalt behave: thin walls pale, thick bases deep.

## 11. Open decisions

**Mesh budget.** 474 KB / 13,442 verts per body; 20 MB for the set. Heavier than
a browser needs when loading a body + cap + roller.
- `--segments 64 --profile-points 96` → roughly a third, no new dependency
- Draco (`export_draco_mesh_compression_enable` in `export_glb()`) → typically
  5–10× smaller, but the r3f loader needs the Draco decoder wired first

**No UVs.** Correct for glass and env-map reflections. A blocker only if you
later want printed labels or decals — re-exporting 42 files is trivial now and
painful after the configurator ships.

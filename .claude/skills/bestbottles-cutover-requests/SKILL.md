# Best Bottles cutover requests

- **Live form:** https://claude.ai/artifact/ScK99Dz3LU5RVgkwQpy61u
- **Source:** `docs/cutover-requests/cutover-requests.html`
- **Answers record:** `docs/cutover-requests/ANSWERS.md` and `answers.json`, generated by `scripts/cutover_answers_report.mjs`
- **Request-to-code map:** `docs/cutover-requests/README.md`

The page saves answers in its own database: collection `answers`, one document per request code, shaped `{ v, note, by, at }`. `v` is the option's exact wording for a choice, an array of option wordings for a multi-select, an object keyed by field for a fields request, or free text. `at` is milliseconds since 1970. The page ignores documents whose id is not a request code.

## Sync the answers into the repo

1. Read every answer with the ArtifactData tool: `action: "list"`, `url` the live form, `collection: "answers"`, `query: { limit: 200 }`, `out_dir` a fresh folder in your scratchpad. Each answer lands as `<out_dir>/answers/<code>.json`, a bare `{ v, note, by, at }` document.
2. If any document has a `by` id, get names with ArtifactData `action: "profiles"` and those ids, and save `{ "<id>": { "name": "<name>" } }` as a JSON file.
3. Run:
   ```
   node scripts/cutover_answers_report.mjs --export <out_dir> [--names <names.json>]
   ```
4. Read the diff of `docs/cutover-requests/ANSWERS.md` and report what changed: newly answered requests first, launch requests called out, and any "not one of the form's current options" warnings.
5. Never commit raw exports. Only the generated record goes in the repo, and the script has already replaced long digit runs.

## Enter an answer for Jordan

Only when Jordan asks, naming the code and the answer.

1. ArtifactData `get` on `answers/<code>` to see whether it exists and its `version`.
2. Write it with `set` (pass `if_version` if it existed): `{ v, note, by: null, at: <now in ms> }`. For a choice, `v` must be one of that request's `opts` exactly as written in the source; check before writing.
3. Run a sync afterwards so the repo record matches.

## Edit and republish the form

1. Edit `docs/cutover-requests/cutover-requests.html`. Keep request codes and already-picked option wordings unchanged; see the rules in the README.
2. In a new session, read the artifact first (Artifact `action: "read"` with the live URL). A publish to an artifact the session hasn't read is refused.
3. Publish with the Artifact tool: `file_path` the source, `url` the live form. Omit `capabilities` and `icon` so the page keeps its database, its user capability and its icon. Answers survive a republish.
4. If the published page's source differs from the repo copy (someone edited it elsewhere), merge into the repo copy first. Never overwrite newer published content.

## Testing

To test the sync end to end, write one probe document under an id the page ignores (for example `zz-sync-probe`), export, run the script (it lists the probe under ignored documents), then delete the probe with `if_version`. Never write test answers under a real request code.

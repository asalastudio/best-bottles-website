## Voice transcription ordering correction

Re-review of `9369d483` found that speech onset invalidated the old catalogue generation but left it inactive until transcription completed. A legitimate response/tool call can precede that transcription and was therefore rejected as stale. OpenAI documents that transcription runs asynchronously with response creation ([Realtime API reference](https://developers.openai.com/api/reference/go/resources/realtime)), and that completion order across speech turns is not guaranteed; match transcripts by `item_id` ([Realtime transcription guide](https://developers.openai.com/api/docs/guides/realtime-transcription)). The installed OpenAI SDK also documents the speech-start `item_id` as the upcoming user message item's ID.

Accepted speech now starts an active catalogue generation immediately, keyed by that item ID. A matching transcript enriches its request text without advancing generation/revision, clearing queued displays, or discarding verified refinement. Old, interrupted, unidentified or superseded voice transcripts cannot reactivate or reset catalogue ownership. Already accepted speech is not reclassified as echo merely because its transcript arrives while Grace's response audio is playing; echo admission still happens at speech onset. Existing in-flight and delayed-navigation cancellation guards remain in place.

Four new regression cases cover current tools before transcription, late transcript enrichment, out-of-order old/new voice transcripts, typed-turn supersession and interruption. The adapter test invokes the actual generated Realtime tool with deferred completion, proving current work succeeds and old work remains blocked; controller tests retain refinement ownership. This does not infer independent-question text before ASR supplies it, nor claim a physical microphone test. Validation from `9369d483` is historical; the new head requires its own CI/preview checks and independent re-review before release.
